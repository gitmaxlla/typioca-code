# Требования к проекту typioca

Версия документа: 1.0
Дата: 09.11.2026
Проект: форк <https://github.com/bloznelis/typioca>, база `baf4170`.

## 1. О приложении

typioca — терминальный тренажёр скорости печати. Приложение запускается локально,
не требует браузера и регистрации, а встроенные наборы слов работают без сети.
Пользователь выбирает режим, набор и раскладку, вводит текст и получает WPM,
CPM, точность и график по секундам.

**Роли**

| Роль | Что делает |
| --- | --- |
| Конечный пользователь | Проходит тесты, выбирает наборы и раскладку, смотрит результаты |
| Автор наборов слов | Подключает свои списки через TOML, включает и синхронизирует наборы |
| Администратор инсталляции | Запускает `typioca serve` и настраивает SSH-доступ |

**Что уже умеет приложение:** тесты на время, по количеству слов и по количеству
предложений; выбор включённых наборов и раскладки; подсветку ошибок и курсора;
исправление ввода через Backspace и `Ctrl+W`; расчёт WPM, CPM, точности, raw WPM
и прироста к среднему; сохранение последних 25 результатов; SSH-сервер.

**Термины**

- **Набор** — список слов или предложений, встроенный, загружаемый или
  пользовательский (`WordSource`, `WordList`).
- **Раскладка** — JSON-файл с отображением вводимых символов на ожидаемые (`Layout`).
- **Сеанс теста** — одно прохождение от первого символа до завершения (`TestSession`).
- **Результат** — сохранённые метрики завершённого сеанса (`TestResult`).
- **WPM** — слов в минуту с учётом ошибок; **CPM** — символов в минуту.
- **Точность** — доля верных символов среди всех введённых.

## 2. Требования к функционалу

### FR-1. Тест на время

Конечный пользователь может пройти тест на время и получить результат.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: тест завершается по таймеру, показывается экран результатов,
результат сохраняется в `results.json`.

### FR-2. Тест по количеству слов

Конечный пользователь может пройти тест на заданное количество слов.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: после ввода последнего символа показывается экран результатов.

### FR-3. Тест по количеству предложений

Конечный пользователь может пройти тест на заданное количество предложений.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: текст состоит из выбранного числа предложений, после последнего
символа показывается экран результатов.

### FR-4. Выбор набора и раскладки

Конечный пользователь может выбрать включённый набор слов или предложений
и раскладку клавиатуры для теста.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: выбранные значения видны в меню, применяются к следующему тесту
и сохраняются в конфигурации.

### FR-5. Ввод и исправление текста

Конечный пользователь может вводить текст с подсветкой текущего символа, ошибок
и исправлять ввод клавишами Backspace и `Ctrl+W`.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: неверный символ подсвечивается, Backspace удаляет последний
символ, `Ctrl+W` удаляет слово, счётчик ошибок не уменьшается.

### FR-6. Просмотр результатов

Конечный пользователь может просмотреть WPM, CPM, точность, raw WPM, прирост
к среднему и график по секундам после завершения теста.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: экран результатов показывает все перечисленные значения.

### FR-7. Управление наборами и раскладками

Автор наборов слов может включать, отключать, скачивать и удалять наборы
и раскладки, а также подключать собственный список через TOML-конфигурацию.
Приоритет: обязательно. Состояние: уже есть.
Признак выполнения: изменения сохраняются в конфигурации и переживают перезапуск;
ошибка загрузки не удаляет уже существующий файл.

### FR-8. Тест через SSH

Конечный пользователь может пройти тест через SSH-подключение к серверу,
запущенному администратором инсталляции.
Приоритет: желательно. Состояние: уже есть.
Признак выполнения: после `ssh -p 2229 <host>` открывается то же меню, тест
проходится удалённо, результат сохраняется на машине сервера.

### FR-9. История результатов

Конечный пользователь может просмотреть историю сохранённых результатов
по режиму и набору.
Приоритет: желательно. Состояние: нужно сделать.
Признак выполнения: отдельный экран показывает до 25 последних результатов
для выбранного режима и набора; при отсутствии истории показывается пустой список.

### Ограничения NFR

| Номер | Ограничение | Проверка |
| --- | --- | --- |
| NFR-1 | Встроенные наборы работают без сети; сеть нужна только для синхронизации наборов и раскладок | Отключить сеть и пройти тест на `Common words` |
| NFR-2 | Приложение работает в Linux, macOS и Windows в терминале с поддержкой ANSI | `make build-all` собирает все пять целей |
| NFR-3 | Запуск приложения и открытие главного меню занимают не более двух секунд на эталонной машине | Замерить время от команды до появления меню |
| NFR-4 | Данные хранятся только локально в каталогах конфигурации и кэша ОС; телеметрии нет | Проверить пути `typioca.conf` и `results.json`, отключить сеть |
| NFR-5 | Обязательный стек: Go 1.22.1, Bubble Tea, Cobra, Wish, TOML/JSON; СУБД не используется | Проверить `go.mod` и отсутствие обращений к БД |

## 3. Пользовательские сценарии

### US-1. Тест на время (FR-1)

- **Роль:** конечный пользователь.
- **Вход:** запущенное приложение, включённый набор `Common words`, режим
  `Time run`, длительность 15 секунд.
- **Шаги:** выбрать `Time run` → `15` → `Common words` → Enter → ввести текст.
- **Выход:** через 15 секунд открывается экран результатов с WPM, CPM, точностью,
  raw WPM, приростом и графиком; результат сохранён.

**Пример:** ввести 15 слов (75 символов) за 15 секунд без ошибок.
Ожидаемый результат: WPM 60, raw WPM 60, CPM 300, точность 100 %.

**Неполные данные:** если не ввести ни одного символа, таймер не запускается
и результат не создаётся. Если все наборы отключены, пункт показывает
`no wordlist enabled`, а Enter не запускает тест.

### US-2. Тест по количеству слов (FR-2)

- **Роль:** конечный пользователь.
- **Вход:** 25 слов, набор `Common words`, 30 секунд, 0 ошибок.
- **Шаги:** выбрать `Word count run` → `25` → `Common words` → Enter → ввести
  все слова.
- **Выход:** после последнего символа открывается экран результатов.

**Пример:** 25 слов за 30 секунд без ошибок. Ожидаемый результат: WPM 50,
raw WPM 50, CPM 250, точность 100 %.

**Неверные данные:** один неверный символ без исправления, те же 25 слов
за 30 секунд. Ожидаемый результат: WPM 48, accuracy 99,2 %, CPM 250,
raw WPM 50; приложение не блокирует ввод и не завершается с ошибкой.

### US-3. Тест по количеству предложений (FR-3)

- **Роль:** конечный пользователь.
- **Вход:** 1 предложение, набор `Frankenstein sentences`.
- **Шаги:** выбрать `Sentence count run` → `1` → `Frankenstein sentences` →
  Enter → ввести текст.
- **Выход:** после последнего символа открывается экран результатов.

**Неверные данные:** если набор предложений отключён, пункт показывает
`no wordlist enabled`, тест не запускается.

### US-4. Выбор набора и раскладки (FR-4)

- **Роль:** конечный пользователь.
- **Вход:** конфигурация с несколькими включёнными наборами и раскладками.
- **Шаги:** открыть `Config` → включить нужный набор → выбрать раскладку →
  `Ctrl+Q` → выбрать режим.
- **Выход:** набор и раскладка доступны в меню и применяются к тесту.

**Неверные данные:** если набор не синхронизирован или отключён, он не появляется
в списке выбора; тест с ним запустить нельзя.

### US-5. Ввод и исправление текста (FR-5)

- **Роль:** конечный пользователь.
- **Вход:** запущенный тест и текст для ввода.
- **Шаги:** вводить символы, при ошибке нажать Backspace или `Ctrl+W`.
- **Выход:** буфер ввода исправлен, курсор и подсветка обновлены.

**Неверные данные:** Backspace в начале текста ничего не удаляет; `Ctrl+W`
в начале первого слова очищает буфер. Приложение не падает.

### US-6. Просмотр результатов (FR-6)

- **Роль:** конечный пользователь.
- **Вход:** завершённый тест.
- **Шаги:** завершить тест и посмотреть экран результатов.
- **Выход:** WPM, CPM, точность, raw WPM, прирост к среднему и график по секундам;
  результат добавлен в историю.

**Неверные данные:** при первом тесте история пуста, прирост считается от нуля,
экран результатов всё равно открывается.

### US-7. Синхронизация набора (FR-7)

- **Роль:** автор наборов слов.
- **Вход:** экран `Config`, набор `Dracula words` не синхронизирован, сеть доступна.
- **Шаги:** выбрать `Dracula words` → нажать `s` → дождаться загрузки.
- **Выход:** файл `dracula.json` появляется в кэше, отметка `synced` становится
  `[x]`, набор доступен в меню тестов.

**Пример:** Linux, `$HOME/.cache/typioca/words/dracula.json` создан, отметка
`[x]`, набор виден в `Word count run`.

**Неверные данные:** сеть недоступна или GitHub Raw возвращает 404. Ожидаемый
результат: строка набора подсвечивается красным, `synced` остаётся пустым, файл
не создаётся и не удаляется, набор не появляется в меню, приложение остаётся
в `Config` и не завершается с ошибкой.

### US-8. Тест через SSH (FR-8)

- **Роль:** конечный пользователь.
- **Вход:** администратор запустил
  `typioca serve --bind 0.0.0.0 --port 2229 --key typioca`.
- **Шаги:** выполнить `ssh -p 2229 <host>` → выбрать режим → пройти тест.
- **Выход:** открывается TUI, тест проходится, результат сохраняется на сервере.

**Неверные данные:** неверный порт даёт отказ соединения; подключение без PTY
завершается сообщением `not a tty`, тест не начинается.

### US-9. История результатов (FR-9, планируется)

- **Роль:** конечный пользователь.
- **Вход:** несколько сохранённых результатов в `results.json`.
- **Шаги:** открыть историю → выбрать режим и набор.
- **Выход:** список до 25 последних результатов с WPM, точностью и датой.

**Неверные данные:** если истории нет, показывается пустой список без ошибки.
